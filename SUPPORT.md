# Soporte — zedazo

### Propósito de este documento

- **Objetivos:** Orientar a quien abre un issue o pide ayuda: docs, plantillas, seguridad y CoC.
- **Estructura:** Documentación → issues → vulnerabilidades → conducta → tiempos.
- **Contenido a integrar según contexto:** Adapta URLs a este crate público. No copies un desk de SaaS con SLA. Sin tickets internos ni cuentas de usuario.

Antes de abrir un issue revisa estas vías.

## 1. Documentación

- [README.md](README.md) — quick start CLI/GUI y contratos
- [ARCHITECTURE.md](ARCHITECTURE.md) — capas y CI
- [CONTRIBUTING.md](CONTRIBUTING.md) — setup y `make ci`
- [AGENTS.md](AGENTS.md) — contrato para agentes (incluye equivalencia `quality` / `test` / `smoke`)
- [docs/](docs/) — CardDAV, GUI, paridad, deploy

## 2. Issues

Preguntas reproducibles o propuestas concretas: [Issues](https://github.com/Iniciativas-Alexendros/zedazo/issues) (plantillas en `.github/ISSUE_TEMPLATE/`).

No uses un issue en blanco: `blank_issues_enabled` está desactivado.

## 3. Vulnerabilidades

No abras issues públicos. Sigue [SECURITY.md](SECURITY.md).

## 4. Conducta

[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Tiempos de respuesta esperados

- Preguntas y issues: cuando podamos, sin SLA
- Issues con etiqueta `bug`: revisión inicial en 7 días naturales
- Pull requests: primera respuesta en 7 días naturales
- Vulnerabilidades: ver `SECURITY.md`
